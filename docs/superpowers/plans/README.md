# NOFX 无人值守双交易所实施路线

本目录对应 2026-11-06 的 Binance/OKX 合约系统改造。当前交付为设计与实施计划，业务代码尚未修改，自动交易及部署均未启用。

先读[共享设计](../specs/2026-11-06-unattended-futures-design.md)，再按顺序实施：

| 阶段 | 计划 | 交付与独立验收 | 前置 |
|---|---|---|---|
| 01 | [执行安全](2026-11-06-01-managed-execution-safety.md) | 两所环境/身份校验、保护监督、安全减仓、旧执行旁路封锁；保持自动交易关闭 | 设计审阅 |
| 02 | [硬风控](2026-11-06-02-hard-risk-controls.md) | 止损风险定仓、资金账本、原子预算、账户与组合熔断；保持自动交易关闭 | 01 |

共18个可独立验证和提交的任务。每个任务含文件、消费/产出接口、失败测试、实现范围、验证命令和提交步骤；不得并行修改共同的 controller/执行契约。

## 需要审阅的首版取舍

- Binance USDⓈ-M 与 OKX USDT 线性永续；专用子账户、单向逐仓、最多3x。
- 首版自动入场只做固定限价，30s撤余单；每账户一个活动计划，可在两个交易所分别运行。
- 单笔计划风险0.5%、账户/组合在险1%、日亏2%、回撤5%、净RR至少2；默认禁用自动交易。这些是建议默认值，尚非用户批准的实盘额度。
- 保留人工审批及历史计划；托管账户封锁旧 Autopilot/Grid 直接下单，模型仅提供 Idea。
- 可判定问题自动补保护或减仓；未知回执、账实冲突、数据库失败或交易所不可达时冻结新增风险并告警，不承诺无条件自动恢复。
- 单实例；不做双向/全仓、跨所套利、自动划转、HA或新的前端工作台。

## 实施时的共同要求

基线为 `4d11af37b3273220674fc657e0c619439fb04d77`。保护工作区既有 `.gitignore`、`kernel/engine.go`、`provider/localpool/` 改动；提交只暂存任务相关路径。执行前重新检查 HEAD 与diff，若相关接口已有变化，先修订计划中的接口和测试，再实施。

金额用现有 Decimal 与 big.Rat。无新增依赖。所有测试默认临时库/本地HTTP/WS，不读取.env、不调用main、不直接跑可能创建真实客户端的旧全仓测试；禁止将默认跳过sandbox测试报告成真实验收通过。

阶段04的sandbox运行需要用户另行授权专用模拟环境及其凭据读取；live资金、时段、部署和启用同样需另行授权。本轮文档不授权这些动作。
